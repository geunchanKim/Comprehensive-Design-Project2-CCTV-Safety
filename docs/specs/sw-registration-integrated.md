# SW 등록 통합 명세서 원고

작성·통합: 해민. 갱신일: 2026-11-17. 등록 기능 기준: 원격 main `78ac9ba`(근찬 선배와 협의한 main 기준). 문서 작업은 develop에서 관리하지만 등록 본문에 develop 전용 기능을 넣지 않는다. 엣지 원고는 [근찬의 #87 회신](https://github.com/geunchanKim/Comprehensive-Design-Project2-CCTV-Safety/issues/87#issuecomment-6934791146)을반영했다. develop에는 보호구 서버·모델 및 엣지 #90이 추가됐으나 main에는 해당 기능이 없다. 화면 설명은 코드와 대조했으며 성윤의 최종 확인·캡처는 아직 받지 않았다. 제출 완료 문서가 아니다.

## 등록용 본문: 프로그램 목적

본 프로그램은 두 대의 CCTV에서 얻은 사람·물체 탐지 정보를 이용해 현장의 객체 위치를 추정하고, 객체 간 근접 위험과 위험구역 접근·침입을 판단하여 웹 관제 화면에 제공한다. 영상 분석을 수행하는 현장 엣지, 위치·위험을 계산하고 데이터를 저장하는 서버, 상태와 경고를 표시하는 관제 화면으로 구성된다.

## 등록용 본문: 엣지 영상 분석과 전송

본 프로그램의 엣지는 현장에 설치된 두 대의 CCTV 영상을 현장 노트북에서 받아 분석하고, 영상 원본 대신 탐지 정보만 서버로 전송한다. 입력은 RTSP 네트워크 카메라, 웹캠, 영상 파일, 녹화 폴더를 지원하며, 카메라마다 별도 스레드에서 프레임을 받고 연결이 끊기면 다시 연결한다. 두 카메라의 프레임은 수신 시각이 가장 가까운 것끼리 짝지으며, 시각 차이가 50ms를 넘으면 짝으로 인정하지 않는다.

짝지은 프레임마다 YOLO11n 모델로 사람과 물체(의자·캐리어 등)를 탐지하고, ByteTrack으로 카메라별 추적 번호를 유지한다. 서버가 위치를 계산하는 기준점인 발 위치는 자세 추정 모델(YOLO11n-pose)로 찾은 두 발목의 가운데를 사용하며, 발목이 보이지 않거나 물체인 경우 탐지 상자의 아래 가운데를 사용한다.

서버에는 두 카메라를 한 묶음으로 객체 종류, 추적 번호, 신뢰도, 탐지 상자, 발 위치(픽셀 좌표)와 촬영 시각을 보낸다. 미터 단위 월드 좌표 변환은 서버가 카메라 캘리브레이션 정보로 수행하며, 엣지는 이를 위한 캘리브레이션 도구(ChArUco 렌즈 보정, 바닥 마커 기반 카메라 위치·자세 계산)를 함께 제공한다. 화면까지의 지연을 줄이기 위해 수신 후 800ms가 지난 묶음은 보내지 않고, 카메라별 연결 상태 신호(heartbeat)를 1초마다 서버에 알린다. 엣지는 Python, PyTorch, Ultralytics YOLO, OpenCV로 구현했다.

## 등록용 본문: 서버 위치·위험 계산과 저장

본 프로그램의 백엔드는 두 카메라의 영상에서 엣지가 추출한 객체 종류, 카메라별 추적 ID, 발 위치와 촬영 시각을 수신하여 동일 객체를 연결하고 미터 단위의 월드 좌표와 서버 객체 ID를 계산한다. 카메라 캘리브레이션 정보를 사용한 에피폴라 매칭·삼각측량과 평면 투영, 추적 상태 유지를 지원한다. 실시간 입력은 기본 알고리즘으로 처리하며, 저장된 탐지 입력은 다른 캘리브레이션 프로필과 개선 알고리즘으로 재계산할 수 있다.

위치가 계산된 사람–사람 및 사람–물체 사이의 거리를 이용해 근접 주의·위험을 판단한다. 공통 기본 거리는 주의 1.0m, 위험 0.5m이며 전체 위험 분석은 설정으로 켜고 끌 수 있다. 같은 월드 XY 좌표계의 다각형 선택 영역을 API로 저장하고, 사람의 영역 접근은 접근 주의(warning), 내부·경계 진입은 침입(intrusion)으로 판단한다. 침입은 위험(danger) 경고로 연결한다. 경고의 발생·종료·사용자 확인과 조치 기록을 데이터베이스에 저장한다.

관제 클라이언트에는 최신 객체 위치·위험 수준·구역·경고를 현재 상태 조회(snapshot)와 실시간 전송(SSE)으로 제공한다. 카메라별 연결 상태 신호를 탐지 입력과 독립적으로 수신하여 연결 상태를 제공하며, 사용자는 경고 확인 API로 확인 사실과 조치를 기록할 수 있다. 데이터는 PostgreSQL에 저장하고, 처리 결과를 CSV로 내보내 비교·평가할 수 있다. 서버는 Python과 FastAPI로 구현하며 SQLAlchemy·Alembic으로 데이터 저장과 스키마 변경을 관리한다.

본 등록 범위는 영상 탐지·전송, 위치 추정·추적, 근접·구역 판정, 관제 데이터 제공, 경고 저장·확인이다.

## 화면 본문 후보 (성윤 확인 후 등록용으로 확정)

관제 화면은 웹 브라우저에서 동작하며, 구역 평면도 위에 서버가 계산한 사람·물체의 현재 위치와 이동 방향, 위험 수준을 색으로 표시한다. 등록된 위험구역 다각형과 카메라 위치·시야 범위를 함께 그리며, 이동 경로·시야·구역 표시는 켜고 끌 수 있다. 객체를 선택하면 종류와 위치, 어느 카메라에서 추적 중인지 확인할 수 있다.

카메라마다 연결 상태(연결·끊김·미확인)를 표시하고, 위치 정보 갱신이 기준 시간보다 늦어지면 갱신 지연을 알린다. 위험 경고가 발생하면 팝업으로 알리며, 팝업에는 구역과 발생 시각, 객체 간 거리, 지속 시간과 조회한 평면도를 보여준다. 관제자는 현장 무전 지시, 담당자 출동, 오탐 중 조치를 선택하거나 단순 확인할 수 있고, 확인 결과는 서버에 기록된다. 경고 목록도 제공한다.

화면은 서버의 현재 상태, 카메라 상태, 경고 목록을 0.5초 간격으로 조회해 갱신한다. 연결할 서버 주소와 운영 조건(세션·캘리브레이션·알고리즘)은 환경 설정으로 지정하며, 서버 없이 시연할 수 있는 예시 데이터 모드도 제공한다. React, TypeScript, Vite로 구현했다.

### 서버 배포 확인

develop `f03bbde`의 [자동 배포·실험](https://github.com/geunchanKim/Comprehensive-Design-Project2-CCTV-Safety/actions/runs/43996154515)은 test·deploy·experiment 모두 성공했다. 이 커밋에는 #92 보호구 상태 서버 구현과 0014 마이그레이션이 포함된다. 서버 이미지는 Alembic 적용 후 웹 서버를 시작한다. #92 직후 실행은 취소됐지만 최신 커밋의 성공 실행이 이를 대체한다. 실제 보호구 모델 입력부터 화면까지의 검증 완료를 의미하지 않는다. 운영 `ENABLE_RISK_ANALYSIS=false` 기본값을 변경하지 않았다.

### 화면 초안 대조 결과

- `AreaPage.tsx`는 위치와 카메라를 각각 500ms 간격으로 조회하며 오래된 위치 데이터에 갱신 지연을 표시한다. 경고 목록은 `AppShell.tsx`에서 500ms 간격으로 조회한다. 구역 목록은 5초 간격이므로 모든 조회가 0.5초라는 설명은 사용하지 않는다.
- `DangerAlertModal.tsx`는 팝업을 열 때 최신 평면도를 조회한다. 원문의 “발생 순간의 평면도”를 “조회한 평면도”로 수정했다.
- 팝업은 danger·미확인 경고를 대상으로 한다. 주의 경고까지 팝업이 뜬다고 적지 않는다.
- 관리자 알림·경고음 안내 문구만으로 실제 전송·재생 구현을 완료로 기록하지 않는다.
