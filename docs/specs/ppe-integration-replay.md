# 보호구 연동 녹화 재생 테스트 (v93·v94)

작성일: 2026-11-18. 담당: 근찬. 관련: #88, 엣지 #90, 서버 #92·#96, 화면 `feat/frontend-ppe-helmet`

## 요약

- 엣지 → 서버 → 화면 연결은 성공했다. 두 번 모두 서버 전송 실패 0건이다.
- 서버 사람 ID는 3명 → 3개로 끝까지 유지됐지만, 한 사람이 snapshot에서 잠깐 빠지는 일이 자주 있었다.
- 조끼 판별은 정답(착용자 없음)과 맞았다. 안전모는 이 녹화에 착용자가 없어 실제 촬영(안전모 착용)에서 확인한다.
- **경고 ID가 너무 자주 새로 생긴다** (87초 동안 조끼 32~36개, 안전모 33~36개, 근접 47~57개). 원인은 사람이 snapshot에서 잠깐 빠지는 것과 사람-의자 근접 오탐이다.

## 할 일

안전모 판별은 실제 촬영(안전모 착용) 때 확인하고, 지금은 근접 오탐과 짝 끊김, 화면 개선에 집중한다.

### 엣지·AI (근찬)

1. **짝 끊김 원인 확인**: 사람이 snapshot에서 빠진 프레임마다 엣지 전송 기록(cam1·cam2 탐지)과 서버 응답을 대조해서, 엣지 미검출인지 서버 짝 실패인지 나눈다.
2. **근접 오탐 줄이기**: 의자 위치 기준점 개선, 의자 탐지 신뢰도 기준 조정. 정지 프레임 정답(1m 격자)으로 오탐률을 다시 잰다. 멘토 피드백이 오면 함께 반영한다.
3. **실제 촬영 준비**: 안전모·조끼 착용 촬영 계획 (착용/미착용 조합, 0.5m·0.8m 거리 표시). 안전모 판별은 이때 확인한다.

### 서버 (해민)

1. **경고 유지 시간**: 사람이 잠깐 빠졌다가 몇 초 안에 다시 나오면 같은 경고로 이어 본다. 가장 효과가 크다.
2. **보호구 상태 끊김**: 보호구 상태가 3초 만료로 미판단이 됐다가 다시 미착용이 될 때도 같은 경고로 이어 볼지 정한다.
3. **입력이 끊긴 세션의 남은 경고**: 언제 닫을지 정한다.
4. 엣지 1번에서 서버 짝 실패로 나오면 원인 확인을 같이 한다.

### 화면 (성윤)

1. **경고 카드를 사람별로 묶기**: "사람 #29 · 조끼·안전모 미착용"처럼 한 장으로. 근접 경고는 따로 둔다.
2. **카드 문구 정리**: 영어 클래스 이름을 한글로(사람, 의자), 제목·설명 반복 없애기, 주의 단계는 "근접", 위험 단계만 "충돌 위험".
3. **평면도 확대**: 카메라가 보는 범위나 사람이 있는 범위에 맞춰 자동으로 확대. 점과 글자 크기 키우기.
4. **겹침 줄이기**: 거리 표시를 선 가운데에 두고 사람 번호와 겹치지 않게.
5. **배지 의미 분명하게**: "조끼 ✕", "안전모 ✕"처럼 미착용이 바로 보이게. 한 사람에게 둘 다면 한 배지로.
6. 경과 시간 표시는 서버 1번이 들어간 뒤 다시 본다.

### 함께

- 서버 1번과 화면 1·6번은 같이 정한다 (경고를 언제 같은 것으로 볼지).
- sc10 위험 팝업 → 확인 공동 검증 (남은 계획 항목). 일정 정하기.
