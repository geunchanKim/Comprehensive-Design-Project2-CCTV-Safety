# 보호구 연동 녹화 재생 테스트 (v93·v94)

작성일: 2026-11-18. 담당: 근찬. 관련: #88, 엣지 #90, 서버 #92·#96, 화면 `feat/frontend-ppe-helmet`

## 요약

- 엣지 → 서버 → 화면 연결은 성공했다. 두 번 모두 서버 전송 실패 0건이다.
- 서버 사람 ID는 3명 → 3개로 끝까지 유지됐다.
- 조끼 판별은 정답(착용자 없음)과 맞았다. 안전모는 미판단이 많고, 야구 모자를 착용으로 보는 경우가 있다.
- **경고 ID가 너무 자주 새로 생긴다** (87초 동안 조끼 32~36개, 안전모 33~36개, 근접 47~57개). 남은 일의 1순위다.

## 조건

| 항목 | 값 |
| --- | --- |
| 녹화 | `classroom/s10/t1` (cam1·cam2, 1920×1080, 87초, 사람 3명, 보호구 착용자 없음) |
| 서버 | 데모 API `:32132`, 커밋 `290ec11`, 보호구 3회 확정 · 신뢰도 0.4 · 유지 3000ms, 위험 분석 켬 |

```bash
cd ai
venv/bin/python edge/realtime.py --cam1 runs/real/classroom/s10/t1/cam1 --cam2 runs/real/classroom/s10/t1/cam2 \
  --no-save --send --server http://<데모 서버>:32132 --session classroom-1014-s10-t1-v94 --ppe
```

서버 상태는 재생하는 동안 `GET /dashboard/snapshot`을 0.5초마다 조회해 저장했다(조회만 함). snapshot은 그 순간의 상태만 주기 때문에, 확정·만료·경고 변화는 이 기록으로 본다. 두 번 모두 재생 시작 약 1초 뒤(서버 seq 5)부터 기록했다.

기록 위치 (git에 올리지 않음): `ai/runs/edge/classroom-1014-s10-t1-v9{3,4}/`(엣지 전송·응답·시간), `ai/runs/integration/v9{3,4}/`(snapshot, 종료 후 alerts).

| 항목 | v93 (18:00:23~18:01:45) | v94 (18:08:42~18:10:05) |
| --- | --- | --- |
| 서버가 받은 탐지 묶음 (201) | 844 / 844 | 786 / 786 |
| 오래돼서 버림 (stale) | 1 | 1 |
| heartbeat (204) | 176 | 실패 없음 (개수 미기록) |
| 같은 카메라 묶음 간격 중간값 / 90% | 95 / 166ms | 100 / 173ms |
| 서버 응답 시간 중간값 / 90% | 43 / 87ms | 43 / 90ms |
| 엣지 수신 → 전송 중간값 / 90% | 143 / 201ms | 150 / 222ms |
| 화면 표시 | 실패 (화면 쪽 연결 설정 문제) | 정상 (성윤 확인) |

- 묶음 수 차이(844 → 786)는 엣지 처리가 밀려 건너뛴 묶음 수가 재생마다 조금 달라서 생긴다. 녹화는 초당 23짝이고 엣지는 초당 약 10짝을 보낸다.
- v93 화면 실패는 서버 문제가 아니었다. 화면과 같은 요청을 `:32132`에 직접 보내면 v93 데이터가 정상으로 나왔다.

### 2. 사람 ID

| 항목 | v93 | v94 |

| 서버 사람 ID | 13, 14, 17 (3개) | 25, 26, 29 (3개) |

### 3. 보호구

snapshot에 나온 사람 상태를 모두 센 값이다(재생 후 남은 snapshot 포함).

| 항목 | v93 | v94 | 해석 |
| --- | --- | --- | --- |
| 조끼 미착용 / 미판단 | 321 / 66 | 607 / 61 | 정답(착용자 없음)과 맞음 |
| 안전모 미착용 / 착용 / 미판단 | 143 / 60 / 184 | 140 / 70 / 458 | 위에서 보면 머리가 작아 미판단이 많고, 야구 모자를 착용으로 봄 |

- 새 사람은 재생 시작 1초 안에 상태가 확정됐다.
- 미판단을 미착용으로 바꾸지 않는 규칙은 서버·화면 모두 지켰다.

### 4. 경고

snapshot에 나온 경고 ID별로 마지막 상태를 모은 값이다.

| 종류 | v93 경고 ID 수 | v94 경고 ID 수 | 지속 시간 중간값 (v93) | 2초 안에 끝난 비율 (v93) |
| --- | --- | --- | --- | --- |
| 조끼 미착용 | 32 | 36 | 2.7초 | 11 / 32 |
| 안전모 미착용 | 33 | 36 | 1.4초 | 22 / 33 |
| 근접 (주의) | 57 | 47 | 0.4초 | 50 / 57 |

- **경고가 끊기는 원인**: 사람이 snapshot에서 잠깐 빠지거나 보호구 상태가 3초 유지 후 미판단으로 바뀌면 경고가 바로 끝난다. 다시 나타나면 새 ID가 된다.
- **근접 경고의 원인**: v93 57개 중 54개, v94 47개 중 45개가 사람-의자 쌍이다. 실제 거리 1.0m 경계에서 생기는 오탐(의자 위치 오차)과 같은 문제다. 위험(0.5m) 경고는 없었다.
- **끝난 뒤 남은 경고**: 두 번 모두 조끼 경고 1건이 active로 남았다. 새 입력이 없으면 경고가 닫히지 않는 서버 동작이다(조회만으로는 상태가 바뀌지 않음).
