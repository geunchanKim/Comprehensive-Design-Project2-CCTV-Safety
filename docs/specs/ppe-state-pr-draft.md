# 보호구 서버 PR 검토안

제목: `feat: 사람 ID별 조끼·안전모 상태 유지 및 관제 제공`

대상: `feat/server-ppe-status` → `develop`, 관련 이슈 #88.

## 한 일

- 사람 탐지의 선택 보호구 관측을 서버 객체 ID에 연결하고 DB에 저장합니다. 같은 결과 3회 일치 시 확정하며 상충·낮은 신뢰도·만료는 unknown으로 제공합니다.
- 같은 추론 시각의 캐시는 중복 누적하지 않습니다. 1초 간격 관측이면 첫 관측 후 2초에 확정되며 마지막 추론 후 3초를 초과하면 만료됩니다.
- 탐지 응답·snapshot에 조끼·안전모와 평가 여부를 제공합니다. 실패 입력의 상태 롤백과 원본 관측 기반 재계산을 지원합니다.
- 0014 마이그레이션, health, Compose·환경변수 예시, JSON Schema·계약·단계 계측을 반영했습니다.
- 11/17 백엔드 전체 SQLite 127개·엣지 47개 통과. 판별 간격 회귀 검사 추가 후 보호구 테스트 13개 통과. 11/16 별도 PostgreSQL 전체 127개 및 마이그레이션 검증 기록은 검증 문서를 참고합니다.

## 할 일

- 실행 전 PostgreSQL에 `python -m alembic upgrade head`로 0014를 적용합니다.
- 서버 반영 후 실제 엣지 전송 샘플·판별 간격으로 ID 연결·상태 전이와 화면 표시를 확인합니다.
- 미착용 경고 등록과 경고음은 후속 범위입니다. 이번 PR로 배포·실제 모델 성능·종단 검증 완료를 선언하지 않습니다.

## 어려운점

- 모델 추론 시각을 프레임 시각으로 바꿔 전송하면 새 관측으로 잘못 누적됩니다. 캐시의 원래 시각 유지가 필요합니다.
