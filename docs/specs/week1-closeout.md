## 연동 리뷰 합의

### 전달 방식

서버→화면 전체 snapshot 전달은 **SSE 우선**으로 FE와 합의했다. 2주 차에는 최신 snapshot GET으로 500ms polling 연결을 먼저 검증하고 SSE를 연결한다. GET·SSE 모두 같은 snapshot과 운영 조건 선택 규칙을 사용한다. WebSocket이 필요한 양방향 요구가 있다면 리뷰에서 대안을 결정한다. 현재 endpoint가 제공된다는 뜻은 아니다.

- 같은 `stream_id/seq`를 반복 조회한 응답은 새 snapshot으로 적용하지 않고 stale 타이머도 연장하지 않는다.
- SSE 연결 유지 메시지도 snapshot 갱신으로 보지 않는다. 새로 적용할 snapshot이 1000ms 이상 없으면 갱신 지연으로 표시한다.
- 재접속 시 현재 snapshot부터 받으며 느린 수신자에게 과거 snapshot을 무제한 적재하지 않는다.
- 운영 조건은 명시적으로 지정한다. 접근 권한·구독 조건·재접속 규칙은 API 공개 전 확정한다.

### 지도 범위 밖 표시

`unity-world-xzy`와 X 2.79~7.79 / Y 1.785~6.785m 범위를 유지한다. 서버는 범위 밖 객체를 snapshot에서 삭제하지 않는다.

- 객체 아이콘은 지도 내부만 표시하고 범위 밖 객체 수를 별도로 알린다. 경고 목록은 필터링하지 않고 지도 밖 배지를 붙이는 안에 FE가 동의했다.
- 위험구역·주의 띠는 원래 좌표로 계산하고 그리기에서 지도 경계로 클리핑한다. 주의 띠 왼끝 X=2.5m가 지도 밖 0.29m인 점을 경계 표식으로 알린다.
- 표시를 위해 좌표를 경계로 옮기거나 구역·주의 거리를 줄이지 않는다. 화면 밖 위험을 안전·미존재로 해석하지 않는다.
- 실제 마커 원점 지도는 다른 frame ID·범위로 2~3주 차에 별도 합의한다.

위 두 안은 #72 FE 회신으로 확정하고 [snapshot 명세](dashboard-stream.md)에 반영했다. 생성 시점·204 응답·GET stream 초기화 규칙도 같은 문서에 정리했다.

## v7 로그 인수와 비교 절차

1. `classroom-1014-v7.txt`와 실제 폴더의 15세션이 정확히 대응하는지 확인한다. 누락 세션·중복 실행·다른 profile/algorithm을 분리한다. v6 로그와 합산하지 않는다.
2. 실행 커밋·모델/장비·시작/종료 시각·실행 설정과 서버 배포/health를 기록한다. v6의 발목 상한/매칭 거리 0.4/2.0m와 v7의 0.15/1.5m 차이를 명시한다.
3. 각 폴더의 `timings.jsonl`, `sent_detections.jsonl`, `responses_detections.jsonl`을 연결하고 실패 파일이 없을 때도 status의 dropped/network-error를 확인한다. 정상 상태의 실패 파일 부재와 필수 로그 누락을 구분한다.
4. 서버 timings가 실제 응답에 존재하는지 확인한다. v7은 계측 배포 후 측정이므로 누락을 정상적인 계측 전 상태로 넘기지 않고 수집/배포 조건을 점검한다. 없는 값은 0으로 채우지 않는다.
5. 세션별 관측 pair 합집합의 첫 5짝을 시간 통계에서 제외한다. 실패·누락·버림 수는 예열 포함 전체 기록으로 집계한다. 유효 표본 수는 재생마다 달라질 수 있어 v6의 2,809개와 같다고 가정하지 않는다.
6. 전체·세션별 평균/P50/P90/P95/최댓값과 입력 수신 시각 기준 전송률을 산출한다. 전송률을 서버 완료율로 부르지 않고 RTT를 화면까지의 전체 지연으로 해석하지 않는다.
7. `session/profile/algorithm + frame=pair_id`가 일치하는 표본에서만 RTT와 서버 total을 비교한다. 차이는 네트워크·함수 외부 처리 잔여 시간이며 순수 네트워크 시간이 아니다. 음수·누락·대응 실패가 있으면 먼저 원인을 확인한다.
8. 실제 서버의 평균 비용과 P95, 세션별 반복성을 함께 보고 개선 후보 2개를 선정한다. v6/v7 설정 차이가 있으므로 속도 차이를 계측 도입만의 효과로 결론 내리지 않는다.

저장소 루트에서 실제 받은 15개 폴더를 확인한 뒤 실행한다. 아래 경로는 수신 후 사용할 예시이며 현재 v7 자료가 존재한다는 뜻은 아니다.

```powershell
$v7Folders = @(Get-ChildItem ai/runs/week1-v7-received/edge -Directory | Select-Object -ExpandProperty FullName)
if ($v7Folders.Count -ne 15) { throw 'v7 세션 폴더 15개를 먼저 확인하세요.' }
python -m backend.tools.measurement_report @v7Folders --warmup 5 --out ai/runs/week1-prep/measurement-v7-all.md
```

명령 성공만으로 완료 처리하지 않고 위 인수 기준과 서버 timings 유무를 함께 검토한다. 확인된 결과만 `docs/benchmarks/`에 옮긴다. 미수신 결과를 채운 비교표나 최적화 순위는 만들지 않는다.
