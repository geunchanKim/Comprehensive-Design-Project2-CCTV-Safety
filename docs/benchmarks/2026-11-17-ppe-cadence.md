# 사람별 보호구 판별 간격 실측 공유

2026-11-17 근찬 선배가 해민에게 전달한 실측 자료를 기록한다. 수치는 담당자 보고이며 이 문서 작업에서 재측정하지 않았다. 측정 기준은 엣지 `feat/edge-ppe`의 `a673d3c`(#90), 모델 v1은 `d582713`(#89)이다. #90 head `d111bae`는 문서 작업 중 develop `67afb02`로 병합됐다. 보고 기준 커밋과 병합된 코드를 구분한다.

등록 기준 main `78ac9ba`에는 이 보호구 엣지·서버 기능이 없으므로 아래 내용을 등록용 기능 본문에 포함하지 않는다. develop의 서버 상태·경고 구현과 향후 연동 검토에 사용하는 참고 자료다.

## 판별 동작과 설정

엣지는 카메라별 추적 ID마다 마지막 판별 시각을 기억해 기본 500ms가 지난 사람만 재판별한다. 카메라당 한 프레임 최대 4명이며 처음 판별하는 사람, 마지막 판별이 오래된 사람 순으로 선택한다. 추적 ID가 없거나 사람 상자 높이가 48px 미만이면 판별하지 않는다.

판별한 프레임에만 안전모·조끼 상태와 `observed_at_ms`를 붙인다. 판별하지 않은 프레임은 필드를 생략하고 캐시를 다시 보내지 않는다. `observed_at_ms`는 해당 프레임의 `ts`(카메라별 보정 수신 시각)와 같다. 서버 벽시계의 추론 완료 시각으로 바꾸지 않는다.

| 항목 | 기본값 | 옵션 |
| --- | --- | --- |
| 같은 사람 재판별 간격 | 500ms | `--ppe-interval-ms` |
| 프레임당 판별 인원, 카메라별 | 최대 4명 | `--ppe-max-people` |
| 보호구 최소 신뢰도 | 0.4 | `--ppe-conf` |
| 제외 사람 상자 높이 | 48px 미만 | 고정 |
| 보호구 모델 입력 크기 | 320 | 고정 |

보호구 판별은 `--ppe`로 켜며 기본은 꺼짐이다. 간격 설정은 0ms 이하 또는 3000ms 이상이면 거부한다. 이는 기본 서버 유지 시간과 맞춘 입력 검증이지, 인원이 많아도 실제 재판별 간격이 항상 3초 미만이라는 보장은 아니다. 서버 `PPE_MAX_AGE_MS`를 override하면 엣지의 고정 3000ms 검사만으로 호환성을 보장할 수 없으므로 실제 실행값을 함께 확인한다.

## 담당자 보고 실측

강의실 녹화 s10-t1의 300짝, 두 카메라, Apple M3 Pro(MPS). YOLO11n 탐지 입력 1280 + 자세 추정 + 보호구 입력 320. 두 카메라 합산 짝당 평균 5.9명이다.

| 판별 설정 | 실제 동일 사람 간격 중간값 / 90백분위 | 짝당 판별 인원 | 초당 처리 짝 |
| --- | --- | --- | --- |
| 보호구 끔 | - | 0 | 12.5 |
| 매 프레임 전원 | 33ms / 74ms | 5.9 | 8.0 |
| 500ms 기본 | 526ms / 579ms | 0.45 | 11.5 |
| 1000ms | 1023ms / 1062ms | 0.24 | 11.9 |

실제 간격은 설정 시간이 지난 뒤 도착한 프레임에서 판별하므로 설정값보다 길어진다. 매 프레임 전원 판별은 초당 10짝 목표에 미달했고, 500ms 설정은 이 측정 조건에서 11.5짝이었다. 동시에 여러 사람이 처음 나타난 프레임은 최대 145.6ms가 보고됐다. 다른 장면·인원·장비의 처리량이나 카메라→화면 종단 지연 보장으로 해석하지 않는다. “매 프레임 전원”은 기본 카메라당 4명 제한과 별도의 비교 측정 설정이다.

## 서버 확정 시간 추정과 만료

같은 상태의 유효 관측 묶음이 3회 연속 서버에 도착하면 확정한다. 두 카메라를 한 번의 관측으로 정리하며 카메라 간 상충·낮은 신뢰도·unknown은 누적을 끊는다.

| 상황 | 첫 판별까지 | 첫 판별부터 확정까지 추정 | 총 추정 |
| --- | --- | --- | --- |
| 새 사람, 즉시 판별 가능한 경우 | 추적 ID 생성 후 첫 판별 프레임 | 526ms × 2 ≈ 1.05초 | 약 1.1초 |
| 추적 중 착용 상태 변화 | 다음 판별까지 약 0~0.53초 | 약 1.05초 | 약 1.1~1.6초 |

위 시간은 중간값에서 계산한 설명용 추정이며 서버 확정 지연을 직접 측정한 값이 아니다. 처리·전송 지연, 카메라당 4명 제한에 따른 대기, 가림·추적 끊김, 판정 상충은 제외한다. 기존 엣지 문서의 “500ms면 약 1.5초”와 달리 첫 판별 기준으로는 두 간격을 더한다. 첫 판별 전 대기를 포함하는지 구분해야 한다.

서버는 후속 탐지를 처리할 때 프레임 시각 기준 마지막 판별 후 3000ms를 초과하면 unknown으로 전환한다. 입력 자체가 끊겨 새 snapshot이 없을 때 기존 저장 snapshot을 타이머가 자동 변경하는 것은 아니다. 화면은 `stale_after_ms`를 넘긴 데이터를 미판단으로 다뤄야 한다.
