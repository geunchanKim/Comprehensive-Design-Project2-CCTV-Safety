# 탐지 저장 TrackLink 조회 일괄화

2026-11-07 로컬 실험. 기준 커밋 `7ae95e6`(PR #81), 별도 로컬 브랜치 `perf/batch-track-link-lookups`. 현재 원격 develop `61a69c7`에는 #81과 이 변경이 아직 포함되지 않는다. 자동 배포나 push를 수행하지 않았다.

## 문제와 변경

기존 `_object_id`는 객체 하나마다 동일 실험 조건·카메라·track 쌍으로 TrackLink SELECT를 실행했다. 반복 추적 프레임에서 객체 N개이면 해당 조회도 N회였다. 다중 객체 요청에서는 현재 입력의 track에 해당하는 기존 링크를 한 번 조회해 요청 내에서 재사용한다. 요청 간 캐시, AI/FE 수정, API 필드·오류 계약 변경, 스키마/인덱스·운영 설정 변경은 없다.

실제 매칭이 생겼을 때만 조회한다. 단일 객체 요청과 양 카메라 입력 track 합계가 500을 넘는 요청은 기존 경로를 사용한다. IN 파라미터의 무제한 증가를 피하기 위한 상한이다. 재연결 후보 조회·최근 링크 우선 선택·used_object_ids에 따른 ID 분리 처리는 기존 로직을 유지한다. 기존에 없는 쌍은 기존 재연결 조회와 생성 경로로 간다. 요청 내 추가된 링크를 전역 캐시하지 않는다.

## 측정 조건과 결과

임시 SQLite, Windows/Python 3.12.10, TestClient 동시성 1. 합성 chair 객체 1/5/10/20개를 두 카메라에서 고정 track으로 반복 입력했다. 각 크기별 처음 2프레임을 제외한 12프레임을 측정했다. 카메라 설정·장면·요청 순서와 알고리즘 baseline은 동일하다. BEFORE는 `7ae95e6` api.py, AFTER는 일괄화 코드이며 PR #81의 개선 효과는 이번 감소율에 중복 포함하지 않는다.

| 객체 수 | 요청당 전체 SQL 전→후 | 감소율 | TrackLink SELECT 전→후 | 감소율 |
| --- | --- | --- | --- | --- |
| 1 | 8 → 8 | 0% | 1 → 1 | 0% |
| 5 | 20 → 16 | 20.00% | 5 → 1 | 80% |
| 10 | 35 → 26 | 25.71% | 10 → 1 | 90% |
| 20 | 65 → 46 | 29.23% | 20 → 1 | 95% |

전체 SQL은 SQLAlchemy before_cursor_execute 이벤트의 SELECT/DML 실행 횟수이며 DBAPI commit 자체는 포함하지 않는다. 감소율은 `(전-후)/전*100`. 20객체에서는 전체 SELECT도 24→5회(79.17%)로 감소했다. 초기 생성·재연결·실측 person/cdfg에 이 비율을 일반화하지 않는다.

총 56프레임의 matches/unmatched/risks/settings가 전후 완전히 동일함을 비교했다. 객체 ID·좌표·관측·카메라 track을 포함한다. 교차/오매칭/재연결과 알고리즘별 기존 테스트를 포함한 backend/edge 합계 130개가 통과했다. 추가 회귀 테스트는 1/5/10객체에서 반복 추적의 링크 SELECT 1회와 ID·좌표·track 유지 여부를 검증한다.

요청 지연은 일관된 개선이 없었다. 20객체 중앙값은 248.39→271.68ms, P95는 293.68→286.50ms였다. 두 번의 짧은 순차 실행 결과이며 CPU 기하 계산·호스트 부하·SQLite 비용을 포함한다. P95 표본도 12개로 적다. 지연 개선율·처리량 개선을 성과로 보고하지 않는다. 쿼리 감소만 관측 결과다. PostgreSQL 실측은 수행하지 않았다.

## 재현과 후속

```powershell
python -m backend.tools.benchmark_track_queries --output after.json
$env:DATABASE_URL = 'sqlite:///./query_test.db'
python -m pytest --confcutdir=. -p no:cacheprovider backend/tests ai/tests -q
```

동일 도구를 기준 커밋의 api.py와 수정 버전에서 각각 새 프로세스로 실행한다. 도구는 운영 DATABASE_URL 대신 임시 SQLite 파일을 사용하고 종료 시 정리한다. 원본 결과의 표본·요약·결과 서명은 [JSON](2026-11-07-track-link-queries.json)에 기록했다. 도구가 출력하는 signatures를 직접 비교할 수 있다.

실습 서버 반영 전 별도 PostgreSQL 환경에서 baseline/cdfg, 여러 클래스, 초기 생성·재연결, 조건 분리, 동시성·실제 데이터 규모를 확인한다. 쿼리 수 감소와 DB 부하/지연 개선은 구분한다. 이번 커밋은 #81 위의 로컬 후속이므로 #81 반영 상태를 확인한 뒤 리뷰·push해야 한다.

자소서에 사용 가능한 범위: “합성 20객체 반복 추적 실험에서 객체별 반복 조회를 요청 단위 일괄 조회로 바꿔 요청당 SQL 실행 수를 65회에서 46회로 29.23% 줄였고, 전후 56프레임 결과 동일성과 130개 테스트를 검증했다.” 실제 운영 서버 성과나 29.23% 응답 속도 향상으로 표현하지 않는다.
